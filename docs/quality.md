# Quality

What "good" means for the shipped kit and site, and where v0.1 stands against it. [AGENTS.md](../AGENTS.md#verification) owns how each change is checked. Adapted from Fineliner's quality contract, which adapted Patina UI's.

## Accessibility

Target: WCAG 2.2 AA in every colourway, poster mode on and off, at 375 px and on the desktop ([the plan](plan.md), principle 8). The [accessibility review](accessibility-review.md) records the v0.1 review; its acceptance table lands here when the repair pass is done.

## Phones and page speed

Built for a mid-range Android phone on mobile data. [AGENTS.md](../AGENTS.md#phones-and-page-speed) has the rules every change follows; this section has the numbers they answer to.

### The lab profile

Headless Chrome (the installed Chrome) driven over the DevTools protocol as a Pixel 7: 412 × 915 CSS px at 2.625×, a mobile user agent and touch (`Emulation.setDeviceMetricsOverride`, `setTouchEmulationEnabled`, `setUserAgentOverride`); CPU slowed 4× (`Emulation.setCPUThrottlingRate`); slow 4G, 150 ms round trip, 1.6 Mbps down and 750 kbps up, cache off (`Network.emulateNetworkConditions`, `Network.setCacheDisabled`). Serve the build over a port (`npm run preview`, 4802), never the dev server. Appearance: Sky, poster mode on, grain on.

- **Record** with performance observers added before load (`Page.addScriptToEvaluateOnNewDocument`): `largest-contentful-paint`, `layout-shift`, `longtask` (total blocking time counts from first contentful paint), `event` (duration threshold 16 ms) for taps, and a `MutationObserver` on `astro-island[ssr]` for when each island hydrates. Bytes come from the network log (`Network.loadingFinished`), sizes from `dist/`.
- **Scroll** with `Input.synthesizeScrollGesture`, 5,000 px at 1,500 px/s, while `requestAnimationFrame` records frame gaps and a trace records `Paint`, `RasterTask`, `Layout` and `Commit`. Use `gestureSourceType: "mouse"`: a `"touch"` gesture runs its full time in headless Chrome and leaves the page where it was, which looks perfectly smooth. Always check `scrollY` afterwards.
- **Tap** with `Input.dispatchTouchEvent` (start, 60 ms, end).
- **It cannot show** GPU raster cost or raster memory (headless rasterizes in software on its own threads, which CPU throttling does not slow), sticky hover, the on-screen keyboard, real touch scrolling, Safari, or what the host's compression and caching do once deployed. For those, a Performance trace from a real phone through `chrome://inspect`, and PageSpeed Insights (mobile) after a deploy.
- Runs vary: home's total blocking time ranged 0–670 ms over five runs. Take three runs before calling a change a gain.

### After the repair pass (2026-11-06)

Landed: fix 2 (frames load one at a time from a queue, near ones first and none while the page scrolls; the frame's block hydrates on idle), fix 3 (the site loads the five faces and the grain as files and preloads Display and Sans Bold; the registry's stylesheet keeps them embedded), fix 4 (all four grain tiles are WebP bitmaps; the mottle is periodic noise drawn as pixels, since the rasterised SVG tile showed its seam), fix 6, fix 7 (Shiki loads when the export comes near), and fix 8 in part (a reroll is a React transition). Fix 5 went to `client:idle` instead of a script. Fix 1 was tried for the chart demo as one hydration boundary per chart and measured worse (about 980 ms against 660 ms), so it was reverted.

### Techniques

| Technique                                                                       | State                                                                             |
| ------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Static HTML first, islands only where something is operated                     | In use; several islands load on the first view that could wait (fixes 1, 2, 5, 6) |
| Follies drawn at build time as inline SVG; a hydrating drawing keeps its markup | In use                                                                            |
| Grain under the content on every surface, scrolled on the compositor            | In use; the docs nav scrolls without repainting                                   |
| Filter-free grain tiles                                                         | In use: WebP bitmaps                                                              |
| First-screen fonts as preloaded WOFF2 files, `font-display: swap`               | In use on the site; the registry's stylesheet keeps them embedded                 |
| A metric-matched fallback font (`size-adjust`, `ascent-override`)               | Not needed while the faces are embedded; needed with fix 3                        |
| Per-demo chunks for docs pages                                                  | In use (`demo-host.tsx` loads one demo by name)                                   |
| `content-visibility: auto` on long pages                                        | In use on the sections of `/letters`                                              |
| Same-origin prefetch through the Speculation Rules API (moderate eagerness)     | Not yet                                                                           |
| Cross-document view transitions (`@view-transition`), none under reduced motion | Not yet                                                                           |
| Back/forward cache: no `unload` handlers, no `no-store`                         | Believed eligible; not checked                                                    |
| Brotli or zstd, a year's cache for hashed files                                 | Not yet; no deployment (fix 9)                                                    |
| `scheduler.yield()` in long work                                                | Not yet: hydration is the long work                                               |

## Where v0.1 stands

- **Loading:** every page paints its largest content in 1.1–2.0 s and does not shift on the lab phone.
- **Over budget:** the chart docs page's hydration (six Recharts charts at once), and JavaScript on the studio, Meridian and chart pages. The other pages measured above block for 0–34 ms at 4× throttling.
- **Not covered yet:** a real phone (GPU raster and memory of the grain, real touch scrolling), Safari and Firefox, field data, and the deployed host's compression and caching.
